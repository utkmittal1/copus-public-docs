A task is a piece of work you asked Copus for. Copus runs two kinds of task and lists them together: a conversation and a scheduled task. A conversation is the ordinary kind, where you say what you need, Copus does it, and you go back and forth in the same thread. Copus works on a scheduled task without you there.

Copus gives every conversation a folder of its own to write files into, called a workspace. Copus gives each scheduled task a folder that holds one workspace per run.

## Start a task

Describe what you need on the Home page and select **Send**. To reach Home from anywhere, select **Home** in the sidebar. Everything that follows belongs to that task: the plan, the tools Copus uses, the files Copus writes, and the approvals Copus asks you for.

Copus names the task for you. Copus uses your first message as the title straight away, shortened if the message is long. A moment later, Copus replaces that stand-in with a short title it writes from the same message. When you rename a task yourself, Copus keeps your title, because Copus replaces only the stand-in title. If Copus can't write a title, Copus keeps the stand-in title.

## Choose which kind of task to start

Most tasks are conversations. You ask, Copus works, and you read the result and ask for the next thing. The rest of this page describes conversations.

A **scheduled task** is for a result you want again and again, such as a brief every weekday morning, or for work done once at a set time, such as booking a court tomorrow at 2. Copus runs the task at the time you agreed and leaves the result for you. [Scheduled tasks](/autonomous/autonomous-tasks) covers them in full.

## Review tasks

When you ask Copus to have a piece of work reviewed, or agree when Copus offers a review, Copus starts a separate task titled **Review:** followed by the file's name. Copus lists the review task with your other tasks, except a review asked for inside an AI team, which stays out of your tasks and search. While that review runs, select the **Reviewing now** card in the chat that asked to open it. Once it ends, open it from a link to it in a team chat, such as one in a teammate's reply.

Copus runs the review task on the same AI provider as the task that asked for it, with the model set for **Session review**, and starts it without that task's conversation. In the review task, Copus reads the files named in the request, checks them against the listed sources and standards, and sends its findings back to the task that asked. Copus leaves the work itself unchanged during a review. A review task runs without your standing instructions and your response style. Copus runs a review task on **Autopilot** with nobody watching, whatever mode the task that asked for it is in, and you can't switch its mode.

## Start a task from another task

A task can start a new task and hand it a brief, the instructions the new task starts from. Ask for one in the conversation, such as "Start a separate task to fix the export bug." Use it to give a side job its own task, or to carry the work on in a fresh task when a conversation has grown long. Copus may also suggest a new task, and starts one only once you agree. In **Manual**, Copus asks you before it starts the task.

The new task is an ordinary task. It runs on the same AI provider and model, and in the same approval mode, as the task that started it, and joins the same project if that task is in one. It can read that task's conversation and files, the files you attached to it, and the folders you added to it, but it can't change those folders.

## The workspace a task writes to

Copus gives each conversation a workspace, a folder only that conversation writes to. The workspace has two parts:

- **`final-output/`** holds the finished deliverables, such as the document, the deck, the spreadsheet, or the analysis.
- **`intermediate-files/`** holds scratch and working material, such as notes, downloads, and half-built drafts.

A task can write files only inside its own folder, and macOS enforces that limit. For a conversation outside a project, that folder is its workspace. For a conversation in a project, that folder is the whole project folder, so conversations in a project can edit each other's files. A conversation can also write in [folders you add to it](#add-a-folder-copus-can-change).

A task can read its own folder, the folders you add, the files you attach, the files other tasks made, and the folders on your **Folders Copus can read** list. That list starts with your Desktop, Documents, Downloads and Pictures folders. The rest of your home folder is closed to it. In a project or AI team set to **Coding**, a task can also read files across your Mac, apart from passwords, keys and sign-ins. See [Work on code](/control/sandbox#work-on-code). In every approval mode, Copus refuses a task's read of a file that looks like it holds a password, such as an `.env` file. [The sandbox](/control/sandbox) covers the boundary in full.

Copus puts the workspace of a conversation outside a project in `CopusData/sessions`, inside your home folder. For a conversation in a project, Copus puts the workspace in that project's `sessions/` folder. For a scheduled task, Copus creates a folder under `CopusData/projects`, and puts the workspaces of the task's runs in that folder's own `sessions/`.

## Add a folder Copus can change

To have Copus work on files where they already live, such as a code repository or a folder of drafts, add that folder to the conversation. From your next message, Copus can read, create, edit, and delete files in it. To let every task read a folder without changing anything in it, add the folder to your **Folders Copus can read** list instead. In **Settings**, select **Built-in tools**, then select the number of folders under **Read files**, such as "4 folders". Copus still keeps its scratch work and finished deliverables in the workspace unless you ask for them in the added folder.

To add a folder:

1. Select the plus button under the message box, then **Add folder**. The **Task actions** menu in the top bar has the same **Add folder** item.
2. Choose the folder.
3. Select **Allow** when Copus asks you to confirm.

Select the folder icon in the message box to see the folders you added. Select a folder's name to open it in Finder. The list has two actions:

- **Remove**: Copus takes the folder off the list, and from your next message it can't write there. Copus leaves the changes it already made in place.
- **Add folder**: Copus adds another folder after you confirm.

You can't add or remove a folder while Copus is replying. To give every conversation in a project the same folder, add it to the project instead. See [The project folder](/concepts/projects#the-project-folder).

### Limitations

- **A conversation holds up to 10 added folders.** Remove a folder to add another.
- **Copus refuses a few folders.** You can add any folder, including a hidden one such as `~/.aws` or one outside your home folder, apart from these:
  - your whole home folder, or a folder that holds it, such as `/`
  - Copus's own folders, `CopusData` and its app folder in `Library/Application Support`, and anything inside them
  - a folder that holds one of Copus's own folders, such as `Library`. Your **Folders Copus can read** list accepts one, because no task can change files there.
  - a folder that holds the temporary files of Copus's tasks, such as `/tmp`
- **Some places stay shut inside an added folder.** The files no task can write anywhere stay blocked in your added folders too. A folder that holds credentials, such as `~/.ssh`, stays shut inside a broader folder you add, and opens only when you add it by name. The sandbox page lists the [blocked files](/control/sandbox#files-no-task-can-write) and the [shut places](/control/sandbox#open-a-shut-folder).
- **Scheduled tasks never get added folders.**
- **Copus never moves, renames, or deletes an added folder.** Deleting the conversation leaves the folder where it is.

## Open the files a task made

Select **Artifacts** in the top bar of a task. The files pane opens beside the conversation, with the task's folders on the left and the open file on the right. The task's finished deliverables in `final-output/` are open from the start. For a task in a project, the folders start from the project, with its shared `artifacts` folder above this task's folder. **Search files** finds a file by its name.

Select **Open folder in Finder**, beside **Search files**, to open the task's whole folder on your Mac. The same item sits in the **Task actions** menu in the top bar.

<Tip>
  Hover a file row to see the file's full path on your Mac. To find the file itself in Finder, use **Show in Folder** in the file viewer's **File actions** menu.
</Tip>

## What belongs to one task alone

Two settings apply to one task alone.

**Instructions.** Select **Instructions** in the task's top bar and write standing guidance for this task, such as "answer in French" or "keep every figure to two decimal places." Copus saves the text as you type, and reads the instructions again with every message. Instructions you want in every task belong on the **Instructions** page in the sidebar. See [Instructions and profile](/context/instructions-and-profile).

**Approval mode.** Each conversation runs in **Manual**, on **Autopilot**, or on **Full access**, set from the controls under the message box. In **Manual**, Copus asks you by default before it sends, posts, or changes anything in a connected app, and before it runs a command that changes something on your Mac. On **Autopilot**, Copus runs commands and makes most changes without asking, and still asks before it sends, posts, deletes, or shares something in a connected app. On **Full access**, Copus runs nearly everything without asking. A new task starts in **Manual**. To start every new task in another mode instead, open **Settings**, select **Built-in tools**, and change **New tasks start in**. A task in a project you pointed at a folder of your own starts in **Manual** either way. See [Approvals and permissions](/control/approvals-and-permissions).

<Note>
  A scheduled task's runs run on **Autopilot**, because nobody is there to answer. When a run tries to read a sign-in Copus keeps, Copus refuses for the same reason. A task's own conversation and a task Copus starts on its own also stay on **Autopilot**, and you can't switch their mode.
</Note>

## Find, rename, pin, move, or delete a task

The sidebar lists your recent tasks under **Tasks**, as many as fit its height. Right-click a task in the sidebar, or select the "…" beside it, for **Pin** and **Delete**, plus the project items such as **Add to project** for a conversation. Select **View all** beneath the tasks for the full list.

To find older work, type into **Search** at the top of the sidebar, or press `⌘K` to put the cursor there. Copus searches your conversations, projects, scheduled tasks, the tasks it started on Home, and your AI teams. It matches the words in their titles and descriptions, and in a conversation's messages. The matches take the place of the sidebar's links and its Tasks list, best match first, and you select one to open it. Put words in quotes to match an exact phrase. A search made only of one- and two-letter words, such as "Q3", matches titles and descriptions alone.

The full list from **View all** has three controls. Type into **Search tasks…** to narrow the list. Use the menu reading **All tasks**, **Scheduled**, or **Digests** to show one kind of task, or **Reminders** to show your [reminders](/working/reminders) still to go off. Select **Pinned**, beside that menu, to see only the tasks you pinned, and **All** to see every task again.

<Steps>
  <Step title="Rename a task">
    Open the task, select **Task actions** in the top bar, then **Rename**. Type the new name and select **Save**.
  </Step>
  <Step title="Pin a task">
    Pin the tasks you keep returning to, such as a task that holds reference material, so they stay easy to find once the list runs long.

    Select **Pin task** from the same menu, or **Pin** on the task's row in the list.
  </Step>
  <Step title="Move a task into a project">
    Select **Add to project** from the menu, then pick a project or select **Start a new project**. For a task already in a project, select **Move to project** to change it, or **Remove from project** to take it back out.
  </Step>
  <Step title="Delete a task">
    Select **Delete**, then confirm in the **Delete task?** dialog. Copus leaves the workspace folder on disk unless you tick **Also delete the folder from disk** first.
  </Step>
</Steps>

To delete several tasks at once, tick their rows in the full list and select **Delete** in the bar above them. The checkbox in that bar ticks every row on screen. When more tasks match than the list has loaded, select **Select all** with the number of matching tasks beside it to include every one of them.

<Warning>
  When you delete a scheduled task, Copus removes the task, its runs, and its folder, and you can't keep the folder. When you tick a mix of conversations and scheduled tasks, the folder option in the delete dialog applies only to the conversations. Copus deletes the folders of the scheduled tasks whatever you tick.
</Warning>

<Note>
  Copus refuses to delete a conversation that is still working, or to move it into a project. Stop the conversation first, or wait for it to finish. You can't rename, pin, move, or delete a scheduled task's own conversation.
</Note>

## Tasks inside a project

Copus keeps the workspace of a task in a project inside the project's folder. The task can read and write across the whole project folder, so tasks in the same project can build on each other's files. Copus still puts a task's own finished work in its `final-output/`. Copus puts work meant for the whole project in the project's **Artifacts** folder, which every task in the project can reach. [Projects](/concepts/projects) covers the shared context in full.
