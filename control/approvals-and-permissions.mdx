An approval is a request Copus puts in front of you before it acts. You decide which actions need an approval with two settings. You run each conversation in **Manual**, on **Autopilot**, or on **Full access**, which you pick from the controls under the message box. Separately, Copus holds a list of tools, the individual things it can do, such as reading a file, running a command, or sending through Gmail. In **Settings**, you choose whether Copus asks before it uses each tool.

This page covers how to:

- [Choose how much Copus does without asking](#choose-how-much-copus-does-without-asking), in one conversation or in every new task

## Choose how much Copus does without asking

In **Manual**, Copus asks you by default before it sends, posts, or changes anything in a connected app, and before it runs a command that changes something on your Mac. On **Autopilot**, Copus runs commands and makes most changes without asking. It still asks before it sends, posts, deletes, or shares something in a connected app, and before it changes anything in GitHub. On **Full access**, Copus runs nearly everything without asking. Sending email, changing your calendar, and sharing or commenting on Drive files are the exception. In every mode, Copus shows you a card for those first, and nothing goes out until you select the button on it.

A new task starts in **Manual**. Switch it to **Autopilot** and only that conversation changes. The next task starts in **Manual** again. To start every new task on **Autopilot** or **Full access** instead, open **Settings**, select **Built-in tools**, and change **New tasks start in**. Copus asks you to confirm in a dialog headed **Start every new task on Autopilot?** or **Start every new task on Full access?**.

Copus sets the mode itself for some conversations. A task in a project you pointed at a folder of your own starts in **Manual** whatever you set, because Copus writes that work into your own files. The [**Side chat**](/working/describing-what-you-need#ask-in-side-chat) drawer starts on **Autopilot**, because Copus answers there on the spot, and you can switch it like any task. A scheduled or multi-step task's own conversation, a task Copus starts on its own, and a review task always run on **Autopilot**, and you can't switch their mode.

<Steps>
  <Step title="Switch to Autopilot">
    Select **Autopilot** in the controls under the message box, then confirm with **Turn on Autopilot** in the dialog headed **Turn on Autopilot for this conversation?**. Select **Cancel** to back out.
  </Step>
  <Step title="Switch to Full access">
    Select **Full access** in the same controls, then confirm with **Turn on Full access** in the dialog headed **Turn on Full access for this conversation?**. The dialog lists what Copus still checks with you about. Select **Cancel** to back out.
  </Step>
  <Step title="Switch back to Manual">
    Select **Manual**. Copus applies the change straight away, without asking you to confirm, including to a task already running.
  </Step>
</Steps>

Copus reads the mode fresh for each request, so Copus applies a switch from the next action of a running task.

<Warning>
  On **Autopilot** and **Full access**, Copus can create or change a record in an app you have connected without showing it to you first. Use **Manual** wherever a change or a message going out would matter.
</Warning>

<Tip>
  Start a sensitive task on **Manual**, watch the first few actions, then switch to **Autopilot** once you can see what Copus is doing.
</Tip>

### What Autopilot and Full access still ask

On **Autopilot** and **Full access**, Copus reads, searches, writes files in the task's folders, and runs commands without asking. The table shows what each mode does in your connected apps and in Copus's browser. Where the table says **Asks every time**, the request leaves out **Always allow in this conversation**.

| Copus wants to | Autopilot | Full access |
|---|---|---|
| Create or change something in a connected app, such as a Notion page, a Linear issue, or a Drive file | Runs | Runs |
| Post a Slack message, or comment on a Notion page | Asks every time | Asks every time |
| Send, comment, invite, notify, or share something in another connected app, such as Linear or Asana | Asks every time | Asks every time |
| Delete something in a connected app | Asks every time | Asks every time |
| Change anything in GitHub, such as opening an issue, commenting, or pushing a file | Asks every time | Asks every time |
| Use a tool that changes something, in a server you added yourself | Asks, and offers **Always allow in this conversation** | Runs |
| Create or change a scheduled task | Runs | Asks every time |
| Open or act on a site Copus's browser holds your sign-in for | Asks once per site, and again after your next message | Asks once per site, and again after your next message |
| Type or upload a file on a website in Copus's browser | Asks once per site, and again after your next message | Runs |
| Open a website Copus doesn't trust in Copus's browser | Asks once per website, and again after your next message | Runs |

Copus can't tell what a tool in a server you added yourself changes, so those tools follow their own row, whatever they do.

## What Copus does without asking

Copus does these without asking, in every mode. It reads a file, searches your files, searches the web, fetches a page, searches your Knowledge Sources, writes a file inside the folders the task can write to, and opens a page in a browser of its own. These actions change nothing outside the task. If Copus asked before each action, you would learn to approve questions without reading them.

Copus also runs a fixed list of read-only programs on its own: `ls`, `pwd`, `cat`, `head`, `tail`, `wc`, `grep`, `rg`, `which`, `whoami`, `date`, `file`, `stat`, `basename`, `dirname`, `echo`, `du`, `df`, and `pdftotext`. All but one of those programs only print what is already there. `pdftotext` writes the text it pulls out of a PDF, inside the folder the task can already write to. Copus runs two more programs without asking in one use each: `sed` when it prints a range of lines, and `pandoc` when it only converts a file. Copus can also create a folder inside the folder it writes to, change directory inside that folder, and run one of its own bundled scripts through the Python it ships.

In **Manual**, Copus asks before a `git` command, even one that only reads, such as `git status`. A project's own git settings can make those commands start another program, and a task can change those settings.

Copus keeps that list narrow on purpose. It asks about any command that redirects output, refers to a shell variable, or builds part of itself from the output of another command, because each of those hides what the command will really touch. Copus allows one variable without asking, the variable naming the Python it ships, because that variable stands for a fixed path Copus wrote. Copus runs a chain of commands without asking only where every part of the chain qualifies on its own. If any single program is off the list, Copus asks you about the whole command.

Copus reads through an integration without asking as well. An integration is the connection Copus holds to an app such as Gmail, Slack, or Linear. Each integration has its own set of tools. Copus sets an integration's reading tools to run on their own, and its writing tools to ask, when you first connect the app.

## Why file writes run without asking

Copus writes a file inside the task's folders without asking, in every mode. The mode sets how Copus handles a request. Copus writes inside those folders without raising a request, so file writes run the same way in every mode.

The folder sets which of your files a write can change. For a task outside a project, the folder is that task's workspace, so your other files stay as they are. For a task in a project you pointed at a folder of your own, the folder is that whole folder of yours. Copus creates files in it, and writes over files you already had, without asking. Copus does the same in a folder you added to the task or to its project.

You can limit these writes in two ways. Set **Edit & write files** to **Ask** on the **Built-in tools** page, and in **Manual** Copus waits for your answer before each write. On **Autopilot** and **Full access**, Copus writes without asking. In **Manual**, Copus also asks before a command that deletes files, such as `rm`, because Copus asks before every command outside the read-only list. On **Autopilot** and **Full access**, the command runs. Otherwise, add a folder, or point a project at a folder, only when you're happy for Copus to change the files in it.

## What Copus asks about

In **Manual**, Copus asks before every command outside the read-only list, and shows you the exact command in the request. It also asks before anything an integration writes, such as a Gmail message, a Slack post, or a new or changed Linear issue.

Copus opens pages, reads them and clicks through them in a browser of its own without asking, on a website it trusts: one you named, or one a task's instructions name. On any other website it asks once first, and your answer covers the whole website. It asks before it types on a site or uploads a file there. It also asks the moment that browser lands on a site you have signed in to through Copus, because that page is your account. Copus asks that in every mode. Your answer covers that one site until Copus comes back to you.

Copus keeps a file its browser downloads only if it is a document, a data file or an image. It asks before it keeps a zip archive.

**Working in the Chrome you are signed in to.** Copus works in your own Chrome only after you switch on **Use my Chrome for sites I’m signed in to** under **Built-in tools**, which needs a one-time browser extension. Even then Copus asks before it acts on each site, in every mode, and your answer covers that one site for the rest of the turn. A turn is one round of work: your message, and everything Copus does before it comes back to you. Send the next message and Copus asks again.

## What Copus asks every time

Copus asks three questions every time they come up. On each, Copus waits for your answer, including on **Autopilot** and **Full access**, and leaves out **Always allow in this conversation**.

**Reading a file that holds credentials.** Copus asks before a task reads any of these:

- A `.env` file, or a file whose name starts with `.env.`, such as `.env.local`. Copus reads a template whose name ends in `.example`, `.sample`, or `.template`, such as `.env.example`, without asking.
- A `.pem`, `.key`, `.p12`, or `.pfx` file.
- A key file named `id_rsa`, `id_dsa`, `id_ecdsa`, or `id_ed25519`.
- A file named `credentials`, `credentials.json`, or `auth.json`, or a file named `secret` or `secrets` that ends in `.json`, `.yaml`, `.yml`, or `.toml`.
- The credentials Copus stores in `CopusData`: your Claude and ChatGPT credentials, and the sign-ins you make in Copus's browser. Copus reads one kind of file there without asking: the files where Claude Code saves a command's output when it is too long to show.

Copus adds whatever a task reads to the conversation and sends the conversation to your AI provider, so Copus leaves this read to you. Copus checks both routes to a file: the file a tool names, and the file a command names in its arguments.

Copus asks this question about a credential file in a folder of your own. Copus refuses a file inside one of the folders it keeps shut, such as `~/.ssh`, `~/.aws` or your keychain folder, without asking you. For every folder and file Copus keeps shut, see [The sandbox](/control/sandbox).

**Publishing work or throwing away changes.** Copus asks before a command that publishes work to a shared repository, such as `git push`, or changes something on GitHub through the `gh` command, such as opening a pull request. It also asks before a command that throws away changes you haven't committed in git, such as `git reset --hard`, `git restore`, or `git clean -f`. Copus asks only about a command it can read. A script that runs one of these commands inside it runs without the question.

**Sending a follow-up to another task.** When one task sends a follow-up message to a task it started, Copus shows you the whole message first and sends it only after you select **Allow**. See [Start a task from another task](/concepts/sessions-and-workspace#start-a-task-from-another-task).

Copus applies the opposite rule to work it runs with nobody watching. In that work, Copus refuses your own Chrome, a website it doesn't trust, typing on a website, a credential file, a push, a change on GitHub, and a command that throws away changes, the moment the question comes up, because nobody is there to answer. Copus applies this rule to a run of a scheduled task, a step of a multi-step task, a review task, and the work Copus does on its own in a task it started or in a multi-step task's own conversation. When you type a message in a task Copus started, or in the conversation **Update task** opens on a task's page, you are there to answer, so Copus asks you. The same holds after you select **Do it**, **Refine**, or **Check in** on a task Copus started.

## What Copus never runs

Copus refuses some commands in every mode, and says why in the conversation:

- A command run as the Mac's administrator, such as `sudo`.
- A command scheduled to run outside Copus, such as `crontab`. A scheduled task in Copus runs work on a timetable instead.
- Shutting down or restarting the Mac.
- Changing macOS's security settings.
- Running one of your Shortcuts.
- Deleting your whole home folder or your whole disk.
- Connecting to this Mac with `ssh`, or handing control of a shell to another computer.

For a command that needs the administrator, run it yourself in Terminal.

## Answer a request

Copus shows the request in the conversation under **Approval needed**, with one line naming the action. Where the exact command or file path adds something the line doesn't already say, select **Details** to see it.

Under that, choose one of three buttons:

- **Deny**: Copus blocks the action.
- **Always allow in this conversation**: Copus takes the action, and answers the same question itself for the rest of that conversation. Copus shows this button only where it can remember the answer.
- **Allow**: Copus takes that one action.

When the action has a scope, Copus names it on the middle button. Approve a `pip install` and the button reads `Always allow “pip install” in this conversation`. The scope is the program rather than the exact command line, so the same approval covers installing a different package. For programs that bundle many verbs, the scope is the program plus the verb. These programs are `git`, `gh`, `npm`, `pnpm`, `yarn`, `pip`, `pip3`, `uv`, `brew`, `docker`, `cargo`, and `go`. Approving `pip install` therefore does nothing for `git push`.

Once you've used that button, Copus lists everything you allowed in the conversation's **Allowed tools** panel, each as a chip. Remove a chip and Copus asks about that action again. What you allow holds for that one conversation, including after you close Copus and come back to it. Copus never applies it to another conversation.

<Warning>
  Copus waits 10 minutes for your answer to a request. After that, Copus skips the action and marks the card **Not answered**. Select **Check in** on the card when you're back, and Copus picks the task back up and asks you again. In a task Copus started, Copus also moves the task to **Needs you** on the Home page.
</Warning>

## Set each tool on its own

The mode covers every question at once. You can also set permissions one tool at a time, and Copus keeps those settings across tasks.

In **Settings**, select **Built-in tools**. The page lists what Copus can do on this machine, alongside the mode new tasks start in. Each row shows whether Copus asks before it uses that capability. Clear a row's checkbox and Copus builds your tasks without that capability.

You can't set **Run commands** to run on its own. A task can read files and reach the network, so Copus's question before a command is the check that stops a task from sending your data somewhere. **Edit & write files** is the one row whose **Auto** or **Ask** setting you can change.

See [Built-in tools](/working/tools) for each capability and its checkbox. See [Integrations](/connections/integrations) for a connected app's own tools, which you set on that app's panel in its **Read** and **Write** groups, each with a checkbox and an **Auto** or **Ask** setting. The **Auto** and **Ask** settings, on those tools and on **Edit & write files**, apply in **Manual**. On **Autopilot** and **Full access**, Copus follows the rules on this page instead.

## Limits that hold in every mode

On **Autopilot** and **Full access**, Copus asks you less often. A task in either mode can do only what it could do in **Manual**, and these limits hold in every mode.

**The sandbox holds in every mode.** macOS refuses a write outside the folders the task can write to, with no question to you, so neither **Autopilot** nor **Full access** can allow the write. [The sandbox](/control/sandbox) covers that boundary.

**A tool you switched off stays off.** Clear the checkbox beside **Run commands** and Copus builds your next task without it. Neither **Autopilot** nor **Full access** can bring the tool back, because the task doesn't have it.

**Copus asks about credential files and your own Chrome in every mode.** Copus leaves both to you, in **Manual**, on **Autopilot**, and on **Full access**.

**Email, calendar changes and Drive sharing always wait for you.** Copus shows you a card in the conversation for an email, an event you create, change or cancel, an answer to an invite, a Drive share or removal, and a comment on a Drive file. You review the card, and the action happens when you select its button. On an email card, select **Save as draft** to put the email in your Gmail drafts instead of sending it. A run of a scheduled task, or a step of a multi-step task, can email and invite only the people you approved for its task. See [Scheduled tasks](/autonomous/autonomous-tasks).

<Note>
  Copus runs the tasks it starts on its own on **Autopilot**. While Copus works on such a task by itself, it only reads your connected apps. Copus sends a reply, creates an event, or makes any other Google change only after you select the button on the task, such as **Send** or **Create event**. After you select **Do it**, **Refine**, or **Check in**, or type a message in the task, Copus works there as it does on **Autopilot** in a task you start. See [Work Copus starts before you ask](/working/before-you-ask).
</Note>
